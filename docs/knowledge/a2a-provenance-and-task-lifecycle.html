A2A 调用来源与持久化 Task 生命周期

本文记录 a2wave 关于 Agent-to-Agent 调用的最终设计：追踪调用由谁发起，并让长时间运行的 A2A 工作不受单条 HTTP 连接寿命限制，同时具备可恢复、可取消、有边界和可观测能力。

仓库：LilithGames/a2wave 协议：A2A 1.0 + 兼容 A2A 0.3 模块：API · Agent Router · CLI runner · Web 功能分支：codex/a2a-task-lifecycle

01 · 实现结果

本次实现解决了什么

远程调用可追踪

双方协商启用可选的调用来源扩展后，被调用方可以记录上游用户名和直接调用它的 Agent。

移除路由器固定五分钟限制

调用方 Agent 的 Run 超时是唯一权威执行预算。路由器不会再因为固定 HTTP 截止时间 到达而终止仍然有效的远程 Task。

可按 Task ID 恢复

一旦取得 Task ID，连接中断后使用 SubscribeToTask 或 GetTask 恢复，绝不重放原始消息。

运行结果。A2A 1.0 长任务可以跨越单条传输连接继续运行，同时仍然受父 Run 超时和取消控制。每个重要生命周期变化都会进入 Run 执行日志。

为什么旧行为看起来不一致

旧路由器为远程 A2A 请求附加了固定五分钟中止信号。调用是否会在五分钟失败取决于传输路径： 持续保持原响应连接的对端会直接受到该期限影响，而较早返回持久化 Task 状态的路径可能呈现 不同行为。最终设计移除了路由器本地执行期限，将短时控制/读取期限与父 Run 的端到端预算 明确分离。

02 · 架构设计

端到端组件流程

sequenceDiagram
    autonumber
    participant U as 用户 / 集成方
    participant C as 调用方 Agent Run
    participant CLI as Agent CLI
    participant R as a2wave Agent Router MCP
    participant A2A as 远程 A2A Agent
    participant LOG as Run 结构化日志
    participant UI as Run 页面

    U->>C: 通过飞书、OAuth、API 或其他渠道触发
    C->>CLI: 携带 timeoutMinutes 和渠道上下文执行
    CLI->>R: invoke_agent / invoke_agents_parallel
    R->>R: 解析 Agent Card 并协商可选调用来源扩展
    R->>A2A: SendMessage 或 SendStreamingMessage
    A2A-->>R: Message 或持久化 Task ID + context ID
    alt Task 尚未到达终态
        loop 直到终态或父调用取消
            R->>A2A: SubscribeToTask 或 GetTask(historyLength=0)
            A2A-->>R: 状态 / artifact / 最终消息
        end
    end
    alt 父 Run 被取消或超时
        R->>A2A: 使用独立 3 秒控制期限发送 CancelTask
        A2A-->>R: 取消状态或尽力而为失败
    end
    R-->>CLI: 最终 MCP 结果
    R-->>CLI: stderr 上的结构化生命周期记录
    CLI->>LOG: 校验并转发安全字段投影
    LOG->>UI: 时间线 + 问题筛选

控制面

  • Agent Card 发现流程选择可用的 JSON-RPC 接口。
  • Capabilities 决定流式传输和调用来源透传行为。
  • 单次请求期限分别约束发现、读取和取消操作。

执行面

  • Agent CLI 将路由器作为 MCP 子进程管理。
  • 父 Run 持有端到端执行预算。
  • CLI 进程组先执行优雅终止，随后才强制清理。

03 · 调用来源透传

可选、可协商、仅用于展示

扩展 URI 同时是其版本化协议标识： https://github.com/LilithGames/a2wave/blob/main/docs/extensions/caller-provenance-v1.md. 它只携带直接调用方 Agent，以及上游渠道已经识别出的用户展示名。

Agent Card 自动协商

1. 被调用方声明支持 A2A 1.0 Agent Card 在可选扩展列表中声明该 URI。
2. 调用方发现并选择接口 路由器选择兼容的 JSON-RPC 接口，并优先选择 A2A 1.0。
3. 调用方激活扩展 URI 同时出现在 A2A-Extensions HTTP 头和 params.message.extensions 中；数据存放在同名 metadata key 下。
4. 被调用方校验后记录 必须同时满足 A2A 1.0、HTTP 层激活、消息层标记和严格 payload schema。无效或未激活 的数据会被忽略，但不会导致 A2A 请求失败。
直连接口规则。直连路由没有 Agent Card 可用于发现可选能力，因此直连 A2A 1.0 必须显式开启发送调用来源信息。该开关默认关闭，A2A 0.3 永远不会发送 此扩展。

Run 列表字段投影

张鑫 · SDK Manager 大神 · A2A SDK Manager 大神 · A2A A2A

已知信息按用户 → 调用方 Agent → 来源顺序展示，缺失层级直接省略。Run 行标题 中的 Agent 是实际执行该 Run 的 Agent；标签中的 Agent 是直接上游调用方。

身份边界。调用来源名称是调用方提供的审计和排障声明。它们绝不会填充权威 user_info、授予权限或替代 API Key/OAuth 传输鉴权。普通 API Key 只能识别 持有凭据的集成，不能识别其背后的最终用户；OAuth/OIDC 可以识别最终用户，是因为被调用方 会校验由已配置 IdP 签发、包含用户身份的令牌。

实际 metadata payload

{
  "https://github.com/LilithGames/a2wave/blob/main/docs/extensions/caller-provenance-v1.md": {
    "userName": "张鑫",
    "callerAgent": {
      "id": "agt_example",
      "name": "SDK Manager 大神"
    }
  }
}
  • 所有字符串都会去除首尾空白，并限制为 256 个字符。
  • payload 必须包含 userName 或 callerAgent。
  • callerAgent 必须包含 ID 或名称。
  • 出现未知字段时，整条声明无效。
  • 不会转发邮箱、手机号、Provider subject、令牌或原始渠道上下文。

04 · 持久化 Task 生命周期

只提交一次，之后按 ID 恢复

flowchart TD
    S([开始调用]) --> M{是否声明流式能力?}
    M -- 是 --> SS[SendStreamingMessage]
    M -- 否 --> SM[SendMessage: returnImmediately=true, historyLength=0]
    SS --> O{是否已观测到 Task ID?}
    SM --> O
    O -- 否，返回 Message --> DONE([返回终态 Message])
    O -- 否，传输失败 --> FAIL([失败且不重放])
    O -- 是 --> T{是否到达终态?}
    T -- 是 --> H{是否已累积可展示结果?}
    H -- 是 --> DONE2([返回最终结果])
    H -- 否 --> BH[GetTask: historyLength=20]
    BH --> DONE2
    T -- 否 --> WAIT[等待流事件或 GetTask: historyLength=0]
    WAIT --> T
    WAIT -- 断线或空闲 30 秒 --> SUB[执行一次 SubscribeToTask]
    SUB -- 成功 --> T
    SUB -- 失败 --> POLL[按退避策略轮询 GetTask]
    POLL --> T
    WAIT -- 父调用取消 --> CANCEL[使用独立 3 秒期限执行 CancelTask]
    POLL -- 父调用取消 --> CANCEL
    CANCEL --> ERR([以 MCP 错误返回取消结果])

提交不变量

原始用户消息只发送一次。在取得 Task ID 前发生的失败无法安全恢复，因此路由器直接 报告失败，不会冒险造成远程任务重复执行。

Task 身份不变量

首次观测 Task 后，Task ID 和 context ID 必须保持不变。发现身份漂移时会拒绝结果， 并尽力取消已知 Task。

进度不是最终答案

working 状态消息可以更新流式 UI，但终态 Task 没有正文时，它不会被误当作成功最终答案。

中断型终态

INPUT_REQUIRED 和 AUTH_REQUIRED 会以非成功结果结束当前无状态 路由调用，同时保留 Task ID 和 context ID。

轮询与终态历史补取

  • 非流式提交和普通轮询使用 historyLength: 0，避免重复传输和解码不断增长的 会话历史。
  • 仅当终态 Task 没有已累积的可展示结果时，才执行一次有界的 GetTask(historyLength: 20) 读取。
  • artifact 分块和消息在提交、重订阅、轮询、终态补取全过程中共享同一个累加器。
  • 完整 Task 快照会替换旧 artifact 快照；增量 append 事件扩展现有 artifact，并拒绝在 已声明最终分块后继续追加。

05 · 超时与安全边界

区分执行时间与控制操作时间

操作 限制 目的
Task 执行 调用方 Agent 的 timeoutMinutes 唯一端到端执行期限；按 Agent 配置。
获取 Agent Card 15 秒 约束发现、DNS 解析、重定向和建连过程。
GetTask 每次尝试 15 秒 防止单次读取永久挂起，同时允许后续重试。
已知 Task 的流空闲 30 秒 触发重连，不会将 Task 判为失败或重放消息。
CancelTask 3 秒 独立于已经中止的父信号，并控制在进程优雅退出窗口内。
CLI 进程优雅清理 发送 SIGKILL 前 5 秒 允许路由器完成尽力而为的下游取消。
Codex 路由 MCP tool 超时 max(660 秒, Run 秒数 + 10 秒) 避免 Codex MCP 超时抢先终止父 Run 和清理流程。
其他 Codex MCP tools 660 秒 保持内置 Agent Router 之外的既有行为。

重试策略

可重试的 GetTask 失败包括 HTTP 408/429/5xx、JSON-RPC internal error、 DNS 解析失败、可识别的网络/套接字错误和请求超时。退避从 1 秒开始，带 0–25% 抖动并按 2 倍增长，本地上限为 30 秒。有效的 Retry-After 秒数或 HTTP-date 优先； 父信号仍可立即中止等待。

16 MiB 单次调用累计远程结果字节上限
10,000 单次调用远程结果事件数量上限
20 终态历史补取的最大消息数

每条远程和 loopback 响应都会在 SDK 缓冲或解码前执行字节限制。已知的非终态 Task 超过 单次调用结果限制时，路由器保留原始限制错误，并先尝试执行 CancelTask。

出站网络策略

  • 只接受 HTTP(S) 路由。
  • 每一跳重定向都会重新校验。
  • DNS 答案经过校验并固定到连接 dispatcher。
  • 默认允许企业私网、CGNAT 和 ULA 目标，但仍阻止 loopback、link-local、云元数据、 multicast、unspecified 和其他保留地址段。
  • 跨源重定向会移除凭据及非安全请求头。

06 · 可观测性

生命周期事件进入普通 Run 日志

Agent Router 在 stderr 输出白名单 JSON 记录。父 CLI runner 扫描物理行但不保留任意 stderr 内容，校验安全字段投影后转发给当前 worker 的结构化日志回调。

事件 含义 问题筛选
a2a.task.observed首次取得 Task/context 身份。否
a2a.task.state已观测 Task 状态发生变化。否
a2a.task.poll_retry正在重试暂时性 Task 读取失败。是
a2a.task.reconnect开始按已知 Task ID 恢复。否
a2a.task.resubscribe_failed流重订阅失败，随后回退到轮询。是
a2a.task.cancel_requested已经尝试取消下游 Task。否
a2a.task.cancel_result下游返回取消状态。否
a2a.task.cancel_failed无法确认取消结果。是

持久化事件示例

{
  "type": "system",
  "subtype": "a2a.task.state",
  "metadata": {
    "target": "Payment Agent",
    "taskId": "task-remote-123",
    "contextId": "context-remote-456",
    "state": "TASK_STATE_WORKING"
  },
  "ts": 1786531200000
}

允许的 metadata 仅包括目标、Task ID、context ID、状态和重试次数。请求正文、凭据、 调用方身份 payload 和任意远端错误对象不会进入生命周期记录。物理生命周期日志行在解析前 已限制长度；超长行会一直丢弃到下一换行符。

10 · 设计决策与易错点

后续修改必须保持的规则

不要重新引入路由器绝对 Task 超时

只有发现、读取和控制操作使用短时期限。长 Task 执行必须继承父 Run 预算。

取得 Task ID 后绝不重放

恢复必须按 ID 进行。重新发送原始消息可能重复执行不可逆的远程工作。

调用来源信息与授权保持分离

展示名称应存入 Run 审计字段；授权继续使用 API Key、OAuth/OIDC 和真实传输安全上下文。

轮询历史必须为空

省略 historyLength 会使 SDK 对端返回完整历史。轮询时使用 0，仅在必要时执行 有界终态读取。

保持单一累计结果预算

只有单响应限制无法阻止长流或重复轮询累积无界数据。

等待进程组清理完成

Worker 处理超时时，必须在路由器收到 SIGTERM 并尝试 CancelTask 期间保持 结构化日志 sink 有效。

A2A 0.3 边界。旧直连路由保持 wire 兼容并继承父取消信号，但按 Task ID 重连和取消的完整保证只适用于标准 A2A 1.0 路径。长时间远程工作应使用 A2A 1.0。

12 · 扩展指南

如何安全演进该功能

  1. 新增生命周期事件：在路由器中输出一条 a2a.task.* 记录， 只在 execution-process-log.ts 增加有界 metadata 字段，补齐 UI 多语言文案， 并明确决定是否应归入问题筛选。
  2. 修改重试分类：更新窄范围分类器，并同时为可重试错误及相近但必须快速失败 的永久错误添加测试。
  3. 新增调用来源字段：如果 wire 语义改变，需要升级扩展 URI 版本。payload 必须继续仅用于展示，并同步更新 Agent Card、发送方、接收方、schema、公开扩展文档和 Run 字段投影。
  4. 新增传输方式：必须保持逐跳校验、DNS 固定、重定向凭据移除、父信号传播、 单响应字节限制和单次调用累计限制。
  5. 支持远程 Task 续接：围绕 Task/context ID 设计显式续接 API。不要静默地将 INPUT_REQUIRED 转换为一次全新提交。

关联修改的最小回归测试集

  • 非流式 Task：SendMessage → GetTask(historyLength=0) → 终态。
  • 流式断线和空闲：重订阅成功及轮询回退。
  • 取得 Task ID 前后的父调用取消。
  • 暂时性 408/429/5xx、Retry-After、DNS 失败及永久错误对照。
  • 终态无输出时补取历史、排除 working 消息及有界历史。
  • Artifact append 连续性、结果字节/事件上限和超限后的下游清理。
  • Agent Card 调用来源协商、直连 v1 显式开启、v0.3 不激活以及仅审计存储。
  • 结构化进程日志、问题筛选、UI 渲染、进程组取消和退出。
