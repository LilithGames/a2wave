# Agent 管理

Agent 是 a2wave 的核心编排单元。一个 Agent = **系统提示词 + 执行引擎（[Provider](/wiki/providers)）+ 挂载的能力 + 触发方式 + 成员**。本章讲清楚怎么建、怎么配、怎么发布与协作。

## Agent 类型

| 类型 | 说明 | 典型用途 |
|------|------|---------|
| **cursor**（默认） | 走 Cursor Agent CLI，具备完整代码编辑 + Shell 执行 | 改代码、跑命令、工程类任务 |
| **llm** | 纯对话/推理，无代码执行 | 问答、文本处理、轻量助手 |
| **script** | 自定义脚本执行 | 固定流程的脚本化任务 |

## 关键配置项

在 Agent 详情页可配置：

- **名称 / 图标 / 描述**：标识信息。
- **系统提示词（System Prompt）**：Agent 的核心人设与规则，支持 Mustache 变量（如 `{{message}}`）。
- **Provider 与模型**：选择执行引擎与具体模型；支持 **Provider 链**（主用 + 回退），最多 5 个，详见下方「Provider 链与失败切换」。
- **推理档位与快速模式**：部分引擎（Claude Code、Codex）支持，配置在**每一档 Provider 的模型旁边**，详见下方「推理档位与快速模式」。
- **凭证模式（authMode）**：
  - `apiKey`：注入 API Key（如 `ANTHROPIC_API_KEY`）。
  - `oauth`：注入 OAuth Token（`CLAUDE_CODE_OAUTH_TOKEN`，仅 Claude Code）。
  - `localSession`：用「运行 a2wave 的服务器」上 CLI 的登录态（`~/.claude` 等，非你当前浏览器所在的电脑），不注入凭证。
- **工作目录类型（workspaceType）**：`temp`（临时目录，默认）或 `scm`（绑定 [代码源](/wiki/scm-sources)）。
- **挂载能力**：[Skill](/wiki/skills) 与 Skill 分组、[MCP Server](/wiki/mcp-servers)、[知识库](/wiki/knowledge-base)。
- **环境变量（env）**：注入子进程；可标记 `sensitive` 做脱敏与克隆清空。
- **最大并发（maxConcurrency）**：1–5，控制该 Agent 同时执行的 Run 数；超出进队列。
- **超时时间**：**单次执行**可设置为 5–120 分钟，默认 10 分钟；到达时限后本次执行会终止。
- **单 Provider 最大重试次数（maxRetries）**：0–5，默认 2，即每个 Provider 最多执行 3 次。
- **总超时时间**：整个 Run 从开始到结束的总耗时上限（含全部重试与 Provider 切换），5–600 分钟；**留空表示不限**（与历史行为一致）。配了 Provider 链时建议设置，避免一次 Run 在多个 Provider 上累计跑很久。
- **长期记忆**：见 [长期记忆](/wiki/memory)。
- **评测**：改完配置后验证效果、对比不同模型，见 [评测](/wiki/evaluation)。
- **发布渠道与触发**：见 [触发方式](/wiki/triggers)。

## 推理档位与快速模式

部分执行引擎（目前是 **Claude Code** 和 **Codex**）允许调节「思考深度」和「输出速度」。这两个开关**跟着模型走**，配置在 Provider 链里每一档的模型下方，而不是整个 Agent 一份——因为链上可以混用不同引擎和模型，各自能选的档位不一样。

### 推理档位

档位越高，模型思考越深入，耗时和费用也越高。**可选档位由所选模型决定**，不是平台写死的：a2wave 在拉取模型列表时一并把该模型支持的档位取回来，所以你看到的选项就是这套凭证下这个模型真正能用的。

- **留空**表示不指定，直接用 CLI 自己的默认档位。
- 换模型后档位选项会跟着变。原来选的档位新模型也有就保持不变；新模型没有这一档时，自动回落到**该模型的默认档位**（拉取不到默认值时留空，运行时即 CLI 默认）。
- 有些模型（例如轻量级模型）本身就不支持推理档位，此时会提示「该模型不支持推理档位」。

> [!NOTE]
> 如果你用的是自建代理地址，代理通常只返回模型名、不返回档位清单，此时选择框会置灰并提示「未拉取到档位信息」。留空即可，运行时会使用 CLI 的默认档位；已经配好的档位不会因此丢失。

### 快速模式

以更高的输出速度运行，通常按更高的价格计费。它是一个纯开关，没有档位可选。

**是否真正生效不由这个开关单独决定**：还取决于所用模型、账号套餐以及接入方式（例如经过第三方代理时通常无法启用）。开关打开后如果条件不满足，本次执行会以正常速度运行，不会报错。想确认某次执行到底有没有用上，看该次[运行记录](/wiki/runs)里的执行参数。

## Provider 链与失败切换

一个 Agent 可以配置**最多 5 个** Provider，按列表顺序组成一条链：第一个是主用，其余是回退。执行失败时按下面的规则决定「原地重试」还是「换下一个」：

| 失败类型 | 行为 |
|---------|------|
| 限流 / 配额（429、session limit、日/周/月额度） | **立即切换**到下一个 Provider——换个账户才是直接解法，不消耗本 Provider 的重试预算 |
| 模型或工具不兼容（模型不存在、不支持工具调用等） | **立即切换**，同一个 Provider 重试不会改变结果 |
| 瞬时故障（超时、网络抖动、5xx、进程启动失败） | **原地重试**，指数退避；用完「单 Provider 最大重试次数」后才换下一个 |
| 鉴权 / 权限（401、403、无权限、内容策略） | **直接失败**，不重试也不切换——换账户同样过不了 |

两条边界：

- **链只走一遍，不循环**。走完最后一个 Provider 仍失败即返回失败，不会绕回第一个重来。
- **切换后会开启新会话**。不同 Provider / 模型之间的上下文不通用，所以回退时不复用原会话。

某个 Provider 回退成功后，接下来 **30 分钟**内该 Agent 会优先直接用它，不再每次都先撞一遍已知失败的主 Provider；30 分钟后自动回到正常顺序。

> 链上启用的 Provider 全部指向已删除的 Provider 时，运行会明确报「没有可用的 Provider」，而不是静默换个引擎跑。把所有 Provider 都手动禁用是允许的（等同于该 Agent 暂不绑定 Provider），此时执行会在引擎层报错。

## 创建 Agent

1. 进入「Agents」页面，点击 **新建 Agent**。
2. 在模板选择框中选「空白创建」或从模板开始。
3. 填 **名称**、**系统提示词**，选择 **Provider** 与模型。
4. 按需挂载 Skill / MCP / 代码源 / 知识库，配置 env 与并发。
5. 保存进入详情页，可继续编辑或发布。

场景模板会预填名称、提示词和安全默认值，帮助你从成熟的工作方式开始：

| 模板 | 适用场景 | 自动预填 | 保存前仍需确认 |
|------|---------|---------|---------------|
| 我的第一个 Agent | 通用问答与轻量任务 | 通用提示词、Claude Code、新手发布引导 | Provider 凭证与模型 |
| 支持调查助手 | 客服、权限与业务问题的只读调查 | 证据链、权限边界、人工升级规则 | 数据源对应的 Skill / MCP / 知识库 |
| 代码库问答 | 解释实现、调用链和配置 | 只读模式、SCM 工作区、代码证据规则 | 已同步的代码源 |
| 代码审查助手 | 审查 MR、PR 或目标 diff | 只读模式、SCM 工作区、严重级别与门禁规则 | 已同步的代码源与验证工具 |
| 事件分析助手 | 告警、日志与指标排障 | 只读模式、时间线、置信度与止损结构 | 日志/监控对应的 Skill 或 MCP |
| 数据巡检助手 | 定时或临时的趋势与异常分析 | 时区、基线、异常分级和报告契约 | 数据源、统计口径与调度/投递配置 |
| 文档维护助手 | 增量文档更新与全量审计 | SCM 工作区、双模式路由、唯一写入目标规则 | 代码源、文档目标及文档 Skill / MCP |
| 生成文件产物 | 报告、CSV、JSON 等可下载文件 | 文件格式、命名、验证与交付规则 | 输入数据与验收条件 |
| 网页应用生成器 | 可在线预览的静态网页应用 | 产物目录、登录可见的 7 天自动分享 | Provider 凭证、模型与页面需求 |

> [!IMPORTANT]
> 模板是**可编辑的起点**，不是生产 Agent 的克隆。它不会携带生产凭证、环境变量值、Provider / SCM / MCP 等实例 ID、成员、发布渠道或接收人。平台模板只会自动绑定系统所有且对所有用户可见的内置 Skill；保存前请复核 Provider、模型、代码源和挂载能力。

## 浏览 Agent 列表

「Agents」页面展示你有权限访问的 Agent：**置顶的 Agent 排在最前**，其余按创建时间由新到旧排列。列表较多时使用页面底部的分页控件切换上一页 / 下一页；当前页会体现在地址栏（如 `/agents?page=2`），刷新或分享链接后仍能回到同一页。如果看不到某个 Agent，先确认是否在后续页面，再检查是否具备 owner / editor / viewer 权限。

## 置顶常用 Agent

把高频使用的 Agent 置顶，让它稳定停在列表顶部，不必翻页查找。

- **怎么置顶**：把鼠标移到 Agent 卡片上，卡片名称右侧会出现一个图钉图标，点击即可置顶；图钉变为实心高亮表示已置顶。再次点击取消置顶。
- **排序规则**：多个置顶项按你**点击置顶的先后顺序**排列——后置顶的排在已置顶项之后；取消置顶后该 Agent 回到普通列表（按创建时间排序）。
- **谁能置顶**：置顶需要对该 Agent 的写权限（owner / editor，管理员亦可）。仅有 viewer 权限时不显示图钉。
- **作用范围**：置顶只改变列表的展示顺序，不影响 Agent 的运行、发布状态或触发行为。

## 生命周期：草稿 / 已发布 / 已停止

| 状态 | 含义 | 外部调用 |
|------|------|---------|
| `draft` | 草稿，未发布 | 不可被外部触发 |
| `published` | 已发布、活跃 | 监听已配置的触发渠道 |
| `stopped` | 曾发布、已停止 | 网关返回 `403 AGENT_NOT_PUBLISHED` |

- **发布**：置为可触发状态（发布后才监听飞书等渠道）。
- **停止**：暂停接收触发（如临时下线飞书连接）。
- **恢复**：把已停止的 Agent 重新置为运行状态。

## 调试

详情页的 **Chat 调试** 无需外部触发即可验证提示词与能力；`viewer` 角色也能调试。调试产生的 Run 按调用者隔离。

## 克隆与 API Key

- **克隆**：复制一份配置，克隆体归当前操作者所有。**出于安全，克隆会清空所有 `sensitive` 环境变量与 Provider 凭证（API Key / BaseUrl / OAuth Token 置空），仅保留 `authMode` 提示你重填**。
- **导入 / 导出**：登录后下载导出包时，管理员可导出全部已挂载 Skill；普通用户只能导出自己拥有或「所有用户」可见的 Skill，不能借 Agent 的查看权限取得他人的私有 Skill。24 小时临时分享链接不包含任何 Skill 内容或附属文件，导入者需要在目标实例自行安装并重新绑定所需 Skill。导出包不会携带 Slack 或 Discord token。导入后这两个渠道保持关闭且配置为空，重新发布前需要填写目标工作区或服务器的真实凭证。上传请求仍受全局 10 MiB 请求体限制；URL 导入最多下载 50 MiB 压缩数据，整体最长 120 秒。解析或写入前，会按压缩包声明的元数据校验以下限制：最多 10,000 个条目、单条与单个 Skill 各 10 MiB、每个 Skill 500 个文件、总解压 100 MiB，并拒绝不安全、重复或越界路径。平台会逐跳校验重定向和 DNS 结果并固定连接；`TRUSTED_IMPORT_HOSTS` 精确白名单只能放行常规企业私网 DNS，回环、链路本地/云元数据（含阿里云与 IPv6 IMDS）、保留地址、通配符和 IP 字面量始终不能放行。
- **重置 API Key**：作废旧 Key 并生成新的网关调用密钥（`POST /api/agents/:id/regenerate-api-key`）。

## 概览与趋势

详情页的 **概览** 标签回答「这个 Agent 用得怎么样」：顶部是累计指标卡（总运行数、成功率、平均时长、今日运行数、Token 用量），下方是 **趋势分析**，把同样的数据摊开到时间轴上，用来判断走势而非只看总量。

**时间范围**：提供「今天 / 近 7 天 / 近 30 天 / 近 90 天 / 自定义」。选「今天」时按**小时**成桶，其余按**天**；自定义区间在 2 天以内也会自动切到小时粒度。没有数据的日子同样会出现在坐标轴上（计 0），所以曲线中断代表「真的没有调用」，而不是数据缺失。

四张图分别是：

| 图表 | 含义 |
|------|------|
| **运行趋势（按状态）** | 每个时间桶的运行数，按成功 / 失败 / 运行中 / 排队 / 等待 / 已取消堆叠，一眼看出某天的失败是偶发还是持续 |
| **提问人数** | 每个时间桶内不同提问者的数量 |
| **Token 用量** | 输入与输出 Token 的消耗曲线，用于观察成本走势 |
| **平均响应时长（每轮）** | 单轮对话的平均耗时 |

> [!NOTE]
> **提问人数**统计每个时间桶内的去重调用者：优先按登录用户身份识别，外部渠道（如飞书）则按调用者名称识别，同一个人从不同渠道进来只算一次。定时任务、纯 API Key 这类不携带调用者身份的运行不计入。

> [!IMPORTANT]
> **平均响应时长（每轮）** 按**单轮对话**统计，而顶部指标卡的「平均时长」按**整次运行**统计。一次多轮运行会在前者中计入多次，所以两个数字不相等是正常的，不是 Bug。

Token 用量按**每一轮发生的时刻**归属：跨天的多轮会话，昨天那几轮算昨天、今天这几轮算今天，而不是全部堆在会话创建的那天。

## 诊断

详情页的 **综合诊断** 一键检查执行引擎、Provider、飞书 / Slack / Discord 连接等状态，是「为什么不工作」的首选排查入口。注意：连接状态只反映当前 API 实例。

## 权限角色

Agent 按 **owner / editor / viewer** 三级隔离（admin 等同 owner）：

| 角色 | 能力 |
|------|------|
| **viewer** | 只读 + Chat 调试 |
| **editor** | 读写 + 发布/停止/克隆/分享 |
| **owner** | 在 editor 基础上可删除 + 管理成员 |

成员添加与管理详见 [成员管理](/wiki/members)。

## 排错

| 症状 | 可能原因 | 解决 |
|------|---------|------|
| 发布后调用 403 | Agent 未发布 / 已停止 | 确认状态为 `published` |
| 执行报错「No engine」 | Provider 未配好或引擎不可用 | 跑「综合诊断」，检查 Provider 凭证 |
| 看不到某 Agent | 无访问权限 | 联系 owner 加你为成员 |
| 改配置报权限不足(403) | 你是 viewer | 需 editor 及以上 |
