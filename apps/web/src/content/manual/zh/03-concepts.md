# 核心理念与架构

理解 a2wave 的设计取向，能帮你判断「一个需求该怎么在平台上落地」。本章讲清楚平台是什么、数据怎么流动、各概念如何咬合，以及不可逾越的产品边界。

## 一句话：编排，不执行

a2wave 是 **编排层**。它负责创建、配置、触发、监控 Agent；而真正的推理与代码执行，交给底层成熟的 agent CLI（Claude Code / OpenAI Codex / Cursor Agent）。平台**不自建** LLM 推理、代码执行或沙箱运行时。

这带来一个直接推论：**没有配置可用的 [Provider](/wiki/providers)，Agent 就跑不起来**——因为执行能力全部来自 Provider 背后的 CLI。

## 整体数据流

```
触发（API / 飞书 / A2A / 定时 / Git 仓库变化）
        │
        ▼
      Agent  ──读取──▶  系统提示词 + Skill + MCP + 知识库 + 记忆
        │
        ▼
   Provider（启动底层 CLI 子进程执行）
        │
        ▼
      Run（记录输入/输出/日志） ──▶  产物 Artifacts
```

每一次触发都会生成一条 [Run](/wiki/runs)，无论来自哪种渠道，执行路径都一致，只是 `triggerSource` 不同。

## 核心概念如何咬合

| 概念 | 角色 | 关系 |
|------|------|------|
| **Agent** | 编排单元 | 引用一个 Provider；挂载 Skill / MCP / 代码源 / 知识库；配置触发与成员 |
| **Provider** | 执行引擎 + 凭证 | 决定用哪个 CLI 与模型执行；被多个 Agent 引用 |
| **Skill** | 可复用能力包 | 以 `SKILL.md` 描述流程/知识，挂到 Agent |
| **MCP Server** | 工具来源 | 通过 MCP 协议给 Agent 提供可调用工具 |
| **SCM 代码源** | 代码工作区 | Agent 在隔离的 worktree 中读写仓库 |
| **知识库** | 可检索资料 | Run 启动时把相关内容注入上下文 |
| **长期记忆** | 跨会话记忆 | 平台自动写日志/洞察，启动时注入 + 按需检索 |
| **Run / 产物** | 执行记录 | 可审计的输入、输出、日志与生成文件 |

> [!TIP]
> 选型口诀:调外部系统/工具用 [MCP](/wiki/mcp-servers);封装流程或知识用 [Skill](/wiki/skills);可检索的事实资料用 [知识库](/wiki/knowledge-base);跨会话的偏好与历史用 [长期记忆](/wiki/memory)。

## 四种作用域：身份、Agent 凭证、部署登录态与 Run

很多人同时调用 Agent 时，下面四种作用域会同时参与，但它们回答的是不同问题，不能理解成四层凭证：

```text
用户 / 调用方身份       谁发起了任务？
          │
          ▼
Agent 的 Provider 绑定   用哪个 CLI、模型、认证方式和凭证执行？
          │
          ▼
部署级 CLI 登录态      localSession 共用服务器上的哪个账号？
          │
          ▼
Run                         哪些执行记录、队列槽、日志和工作区属于这次任务？
```

| 作用域 | 它控制什么 | 它不代表什么 |
|------|--------------|----------------|
| **用户 / 调用方身份** | 触发渠道能识别用户时，用于归属、权限与审计来源 | 不会自动改用该用户个人的模型账号或 API Key |
| **Agent 的 Provider 绑定** | Provider、模型、回退顺序、`authMode` 以及 Agent 级注入凭证 | 共用 Provider 预设不等于所有 Agent 必须共用同一枚 API Key |
| **部署级 CLI 登录态** | Provider 绑定选择 `localSession` 时，使用服务器/容器中已登录的 CLI 账号 | 它不按用户或 Run 隔离；使用同一 CLI 本地会话的 Agent 共用该部署身份 |
| **Run** | 一次任务的生命周期、排队位置、输入/输出、日志、Token 用量与工作区处理 | Run 隔离不会为每个任务自动创建新的模型账号或凭证 |

例如，小李和小王可以同时向同一个发布到飞书的 Agent 发送不同任务。a2wave 会创建两条 Run，并分别记录当前能获取到的调用者来源，但两条 Run 仍使用该 Agent 的 Provider 链。绑定使用 `apiKey` 时，两条 Run 共用保存在该 Agent 绑定上的凭证；使用 `localSession` 时，两条 Run 共用 a2wave 部署机器上的 CLI 登录账号。如果需要使用不同模型账号，应绑定不同的 Agent 凭证（或者使用不同 Agent）；仅仅调用者或 Run ID 不同还不够。

Run 列表中的 Agent 是实际执行本次任务的 Agent；Run 详情与执行日志会展示本次执行中可用的 Provider 尝试和模型活动。普通 Run 保留执行历史，但不会冻结一份可重用的 Agent 秘密凭证副本。评测任务不同：它会冻结 Provider / 模型 / 提示词快照用于对比，且该快照会刻意排除凭证。

> [!CAUTION]
> 不要把 API Key、Token、CLI 凭证文件或原始凭证配置复制到 Run 元数据、日志、审计详情、截图或导出的诊断信息中。

## 六条产品铁律

这些是平台的硬边界，任何功能都不会越过它们——理解它们能帮你少走弯路：

| # | 铁律 | 对你的含义 |
|---|------|-----------|
| 1 | **编排不执行** | 平台不跑模型/代码，能力来自底层 CLI |
| 2 | **扩展靠组合** | 新能力用 Skill + MCP 组合，不硬编码进平台 |
| 3 | **自然语言驱动** | 用提示词和意图配置 Agent，不做拖拽连线的 DAG |
| 4 | **Agent 自治** | 平台不干预运行时推理/工具决策，无「步骤审批」卡点 |
| 5 | **企业级优先** | 认证、限流、审计是刚需；不支持匿名调用。目标是让协作同事之间可追责、按需授权，而不是防范内部恶意使用者 |
| 6 | **门槛靠你自己的本地 Agent 降低，而不是再加一个界面** | 凡是你能让本机的 Claude Code / Codex / Cursor Agent 代劳的事——写提示词、填配置、生成 Agent YAML、调用 CLI——平台不会再包一层向导。它把力气花在只有平台能给你的东西上：运行时、运行记录与诊断、容错、渠道、权限与审计 |
