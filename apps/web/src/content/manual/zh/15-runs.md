# 运行记录（Runs）

Run 是 Agent 的一次执行记录。无论通过哪种方式触发，每次执行都会生成一条 Run，可在「运行记录」中查看——这是企业级可审计性的基础。

## 状态机

| 状态 | 含义 |
|------|------|
| `pending` | 已创建，等待执行槽 |
| `queued` | 在队列中，等 Agent 空闲槽位 |
| `running` | 正在执行 |
| `completed` | 成功完成 |
| `failed` | 执行出错 |
| `cancelled` | 被取消 / 被驱逐 / 触发它的 MR 在排队期间已合并或关闭 |

并发由 Agent 的 `maxConcurrency` 控制：有空槽立即跑，否则进队列。

## 触发来源与调用链

每条 Run 都标注来源：`debug`（Web 调试）/ `api` / `feishu` / `slack` / `discord` / `qq_official` / `a2a` / `schedule` / `oauth` / `chat_app`（对话网页）/ `glab`（GitLab 仓库触发）/ `gh`（GitHub 仓库触发）。运行列表会把已知的调用来源按以下顺序显示在输入意图前：

| 可用信息 | 显示示例 |
|----------|----------|
| 用户、调用方 Agent、途径都已知 | `张鑫·SDK Manager 大神·A2A` |
| 缺少用户 | `SDK Manager 大神·A2A` |
| 只知道途径 | `A2A` |

列表标题中的 Agent 是**本次实际执行的 Agent**；来源标识中的 Agent 是**直接调用它的上游 Agent**。这样既能从三层信息追溯完整调用，也不会因为某一层缺失而隐藏已经确认的来源。

> [!NOTE]
> 身份能否显示取决于触发方式：飞书需要启用并成功解析用户身份；OAuth 渠道可从调用者的 OIDC JWT 识别用户；A2A 只有在对端支持并发送来源扩展时，才能带上调用方 Agent 和上游用户名。SAML 只建立 Web 会话，不会为该渠道产生调用方 bearer token。普通 API Key 只能证明某个集成持有凭据，无法据此判断背后的最终用户，因此通常只显示 `API`。这些名称用于审计和排查；访问权限仍由各渠道的实际鉴权决定，来源扩展不能替代鉴权。

## 查看运行

- **运行列表**：浏览全部 Run、来源与状态。
- **运行详情**：查看本次执行的输入意图、输出结果、聊天记录与运行日志；多步任务含 Run Step。
- **统计概览**：数量、成功率、平均耗时、Token 消耗等。

运行列表分页会同步到地址栏（如 `/runs?page=2`），刷新或分享链接后可以回到同一页。完整日志查看器翻页时也会在当前链接中记录 `logPage`，关闭查看器后自动清除。

## 可见范围

运行记录的可见性跟着 **Agent 权限**走，与 Agent 详情页里看到的会话、统计保持一致：

| 你的身份 | 能看到的运行 |
|----------|--------------|
| 管理员 | 全部运行 |
| Agent 的所有者，或被加为编辑者 / 查看者的[协作成员](/wiki/members) | 该 Agent 的**全部**运行，无论由谁、从哪个渠道触发 |
| 与该 Agent 无关的用户 | 只有自己触发过的运行 |

> [!NOTE]
> 飞书、API Key、OAuth 等渠道触发的运行背后没有登录用户，归属只能由 Agent 决定——所以只要你能打开这个 Agent，就能看到它这些渠道的运行记录。

**动手改的权限比查看更严格**。取消、重新运行、执行都要求你对这条运行有写权限：自己触发的运行算你的，别人触发的则需要该 Agent 的所有者或编辑者权限。「重新运行」还额外要求对 Agent 有写权限——因为它会用 Agent 的凭据和工作区真跑一次，飞书来源的运行还会把回复发回原来的会话。所以查看者可以取消自己起的调试运行，但不能重新运行它。

## Token 消耗统计

当底层 Agent CLI 提供 Token 用量时，a2wave 会记录这些数据，帮助你了解用量分布：

- **仪表盘「Token 消耗榜」**：仪表盘首页在「运行次数排行」「使用人数排行」之外新增 **Token 消耗榜**，按 Agent 汇总 Token 消耗排出 Top 10，用于发现哪些 Agent 消耗量最高。
- **运行详情**：抽屉内展示本次 Run 累计的输入 / 输出 / 推理 / 缓存读取 / 缓存写入 Token。
- **执行日志时间线**：每一轮模型交互的结果条目内联展示当轮输入 / 输出 Token，便于定位单轮消耗异常的步骤。
- 数字较大时以 **K / M / B** 缩写显示（如 `12.3K`、`1.2M`）。
- **失败或取消的运行会保留终止前已上报的用量。** CLI 从未上报的用量无法重建。
- 仪表盘的「今日 Token」按**每轮对话实际发生的时间**归因：昨天创建的会话今天继续聊，消耗计入今天。

页面展示的总量由五个互斥 bucket 相加：**输入 + 输出 + 推理 + 缓存读取 + 缓存写入**。统计不包含、也不展示金额成本。

> [!NOTE]
> Token 统计依赖底层 CLI 上报。聚合值显示 `0` 可能表示范围内没有已上报数据，并不等同于实际消耗为零。历史 Run（功能上线前产生）也没有 Token 数据。

### Provider 统计范围

| Provider | 统计级别 | 说明 |
|----------|----------|------|
| Claude Code | 官方支持 | Result 事件提供输入、输出、缓存读取和缓存写入 Token。 |
| Codex CLI | 官方支持 | `turn.completed` 事件提供输入、输出和缓存输入 Token。 |
| OpenCode CLI | 官方支持 | `step-finish` 事件提供输入、输出、推理和缓存 Token。 |
| Pi CLI | 官方支持 | 每个 Assistant `message_end` 事件提供一次供应商调用的输入、输出、推理、缓存读取与缓存写入用量；`compaction_end` 提供独立摘要调用的用量。a2wave 会累加这些调用，并从 Pi 已包含 reasoning 的 output 中拆出该子集，保证页面上的五个 bucket 互斥。 |
| Cursor CLI | 未上报 | 官方 CLI Result schema 不包含 Token usage；相关统计可能显示为 `0` 或为空。 |
| Qoder CLI | 不适用 | 标准模式按 Credits 计量，不提供可用于本统计的真实 Token；BYOK 不改变当前统计口径。 |
| Trae CLI | 未明确 | 官方未公开 Token usage 事件 schema；仅在 CLI 实际返回兼容字段时才能采集。 |
| Kimi Code CLI | 未上报 | `stream-json` 输出中没有任何 usage 事件；相关统计会显示为 `0` 或为空。 |

## 完整日志（不截断）

运行详情里的执行日志为控制数据库体积，超过条数上限后会**保留开头、丢弃结尾**（出现「日志已截断」标记）。与此同时，每次执行的**全量过程日志**会同时单独写入服务端 NDJSON 文件，长任务后半程不丢：

- **查看完整日志**：执行日志区域点「查看完整日志」，站内查看器按页加载服务端日志，支持按 全部 / 工具调用 / 消息 / 错误-重试 筛选、分页浏览（默认定位最后一页，失败现场优先）。A2A 长任务的轮询重试、重订阅失败和取消失败也会进入「错误-重试」，便于集中查看远程调用恢复问题。
- **下载完整日志**：同区域可下载原始 NDJSON 文件（`GET /api/runs/:id/logs/download`），每行一条 JSON 事件，便于脚本分析。

> 完整日志文件默认保留 14 天（可通过环境变量 `A2WAVE_RUN_LOG_RETENTION_DAYS` 调整），过期自动清理；单文件默认上限 256 MiB。

## 历史记录保留

为避免运行记录长期累积拖慢数据库，平台每天自动清理**超期的已结束运行**（连同其执行步骤与对话消息）以及**审计日志**。管理员可在 [设置 → 产物](/wiki/artifacts) 页调整：

- **历史记录自动清理**：总开关，关闭后所有历史永久保留（适用于依赖外部归档的严格审计部署）。
- **历史保留天数**：默认 **60 天**，删除早于该天数的已结束运行与审计日志。

> [!NOTE]
> 只清理**已结束**（完成 / 失败 / 已取消）的运行；进行中或排队中的运行不受影响。评测任务历史也**不在**清理范围内，以便跨任务对比配置。

## 操作 Run

- **重新运行**：基于已有 Run 再次执行。
- **取消**：`POST /api/runs/:id/cancel`（或网关取消端点），**仅 `running` / `queued` 可取消**。

## 产物（Artifacts）

Run 中产生的文件作为 **产物** 保存，可在产物列表查看与下载，运行结束后仍可追溯（`GET /api/artifacts`、`/:id/download`）。

> 产物是否随磁盘保留，取决于该次调用的 worktree 清理策略（`ephemeral` 立即删 / `ttl` 保留 N 秒 / `persistent` 长期保留），见 [触发方式](/wiki/triggers) 的 `worktree` 参数。

除下载外，产物还能一键生成**在线分享链接**，让对方直接预览网页或报告——见 [产物与在线分享](/wiki/artifacts)。

## 排错思路

1. Run `failed` 或输出为空 → 打开运行详情看错误信息与日志。
2. 怀疑环境问题 → 回 Agent 跑 **综合诊断**（Provider / 引擎 / 飞书连接）。
3. 一直 `queued` → 可能并发已满，调大 `maxConcurrency` 或等待。

OAuth 异步调用查询到 `failed` 时，`data.result.error` 是结构化错误。按 `source` 判断责任方，按 `action` 执行下一步，并在联系 Agent 所有者或平台管理员时附上 `details.runId`。`PROVIDER_*` 不代表调用方的 OIDC JWT 有问题。
